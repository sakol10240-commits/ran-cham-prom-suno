ติดตั้งคลังแพ็กเกจสาธารณะ (Supabase)  ลำดับตามที่ขอ: 3 ฐานข้อมูลและความปลอดภัย -> 2 ต่อเข้าแอพ -> 1 โค้ดที่แก้แล้ว

ขั้นที่ 1  สร้างฐานข้อมูล (ทำครั้งเดียว)
  1. เข้า supabase.com สร้างโปรเจกต์ใหม่ (ตัวเลือก Free)
  2. เมนู SQL Editor > New query > วางเนื้อหาจากไฟล์ supabase/schema.sql ทั้งไฟล์ > กด Run
     สำเร็จแล้วจะมีตาราง song_packages (ล็อกด้วย RLS ไม่มีนโยบายสาธารณะ) กับ view public_song_packages
  3. เมนู Project Settings > API ... คัดลอก  Project URL  และ  service_role key (ลับสุดยอด)

ขั้นที่ 2  ตั้งค่าใน Vercel (Settings > Environment Variables)
  SUPABASE_URL               = Project URL                       (Production)
  SUPABASE_SERVICE_ROLE_KEY  = service_role key  ติ๊ก Sensitive    (Production)
  LIBRARY_SALT               = ข้อความสุ่มยาวๆ (ไม่บังคับ แนะนำ) ห้ามเปลี่ยนภายหลัง ไม่งั้นเจ้าของรายการเดิมจะหาเจอไม่ได้
  APP_ACCESS_CODE และ DEBUG_ERRORS ใช้ตัวเดิมที่มีอยู่แล้ว
  ห้ามใส่ service_role key ในไฟล์โค้ดหรือ GitHub เด็ดขาด คีย์นี้ข้ามกฎความปลอดภัยทั้งหมด

ขั้นที่ 3  อัปโหลดไฟล์ขึ้น GitHub (repo เดิม)
  api/library.js            (ใหม่)
  api/_lib/sanitizer.js     (ใหม่ ต้องอยู่ในโฟลเดอร์ api/_lib)
  index.html, sw.js         (ทับของเดิม)
  ไฟล์ supabase/ และ services/ ไม่จำเป็นต่อการทำงานของแอพ เก็บไว้เป็นเอกสารและโค้ดอ้างอิงได้
  แล้วกด Redeploy

ขั้นที่ 4  ทดสอบ
  - ใส่รหัสเข้าร้าน > สร้างเพลง > กด "☁️ บันทึกออนไลน์ (ส่วนตัว)" > เปิด Supabase > Table Editor > song_packages ต้องเห็น 1 แถว
  - กด "🌐 เผยแพร่ขึ้นคลังสาธารณะ" (กด 2 ครั้งเพื่อยืนยัน) > ปุ่ม "🌐 คลังสาธารณะ" ที่หัวแอพต้องเห็นรายการ
  - ลองเปิดจากเครื่องอื่นโดยไม่ใส่รหัส: ดูคลังสาธารณะได้ แต่บันทึกหรือเผยแพร่ไม่ได้

ดูแลเนื้อหา
  - ถ้ามีรายการไม่เหมาะสม: Table Editor > แถวนั้น > ตั้ง is_hidden = true  รายการจะหายจากคลังสาธารณะทันที
  - เนื้อหาสาธารณะมาจากผู้ใช้ทั่วไป ควรตรวจเป็นระยะ และไม่ควรให้ผู้ใช้ใส่ข้อมูลส่วนตัว
  - ระบบเก็บเฉพาะค่าแฮชของรหัสเครื่อง ไม่มีชื่อ อีเมล หรือ IP ในตารางนี้
  - แผนฟรีของ Supabase อาจพักโปรเจกต์เมื่อไม่มีการใช้งานนาน และมีขีดจำกัดพื้นที่ ตรวจเงื่อนไขล่าสุดในหน้าราคาของ Supabase
